# 上线清单 · 2026-08-19 这一轮（任务台 / 运行中心 / 智能体 / 插件 / 定时任务）

这一轮的东西**三件需要动生产库**。不跑这几条 SQL 的后果分两类：
建表那条不跑是 **500**（页面直接崩），加列/加索引那两条不跑是**静默劣化**（功能不报错但行为不对）。

## 一、生产库手动执行（必做，全部幂等）

在能连到生产库的机器上，或 `docker compose exec web`：

```bash
DATABASE_URL="postgresql://beacon_app:<PWD>@<HOST>:<PORT>/postgres?schema=beacon&sslmode=require" \
  npx prisma db execute --schema prisma/schema.postgres.prisma --file prisma/postgres/12-scheduled-agent.sql
```

四份文件，**按编号顺序**执行：

| 文件 | 做了什么 | 不跑会怎样 |
|---|---|---|
| `12-scheduled-agent.sql` | 建 `ScheduledAgent` 表 + 索引 + RLS 策略 | 智能体页的「定时任务」区 **500** |
| `13-workflow-trigger.sql` | `WorkflowRun.trigger` 列（默认 `manual`）；`AgentRun`/`WorkflowRun` 的 `(status, updatedAt)` 索引 | 运行中心读不到 `trigger` 报错；到期清理走全表扫 |
| `14-workflow-tenant-fk.sql` | 给 `WorkflowTemplate`/`WorkflowInstall` 补租户外键（**先清孤儿再建约束**） | 注销租户后自建智能体留成永远没人清的孤儿行 |
| `15-browser-task.sql` | 建 `BrowserTask` 表 + 索引 + RLS（AI 派给采集插件的活） | AI 的 `dispatch_browser_task` **500**；运行中心也会崩 |

⚠️ `14` 里的 DELETE 是**故意的**：存量库可能已经有指向已删租户的行，
不先清就直接 `ADD CONSTRAINT` 会在部署中途失败。它只删 `tenantId` 指向不存在租户的行，
内置模板（`tenantId IS NULL`）不受影响。

## 二、环境变量

**没有新增。** 定时任务复用现有的 `BEACON_QUEUE=bullmq` + `REDIS_URL`。

## 三、部署后要确认的

1. **worker 起来了、且注册了新任务**。日志里应有：
   `已注册定时任务 jobName=run_scheduled_agents cron=*/10 * * * * tz=Asia/Shanghai`
   没有这行 = 定时智能体永远不会跑（界面上还能配，但不执行）。
2. **内置智能体的职责说明落库了**。第一个访问 `/workflows` 的请求会顺手同步。
   查一下：`SELECT slug, left(persona, 20) FROM "WorkflowTemplate" WHERE "isBuiltin";`
   三条都应该非空——空的话 AI 助手派不动内置智能体（不报错，只是不派）。
3. **浏览器任务的完成/失败会发站内通知**（红点），失败只在**判死后**推一次。
   不需要配置——它走的是已有的站内通知通道，不占机器人推送的订阅。
4. **插件要更新到带「领活」的版本**。旧版插件不会去问 `/api/ingest/tasks`，
   AI 派的活会一直 pending 到 48 小时过期（运行中心里显示「等你的浏览器打开插件」）。
   插件侧的领活挂在已有的两个闹钟上（`beacon-daily` / `beacon-scheduled-collect`），不新开定时器。
5. **推送事件要用户自己勾**。`agent_done`（定时智能体跑完）是新事件，
   存量机器人**不会自动订阅**。要收推送得去「推送与机器人」里勾一次——
   这是刻意的：不替用户决定往他群里推什么。

## 四、这一轮没做 / 做不了的

- **整机版（appliance）不提供定时计划**。它只启一个 `next start`，用的是进程内队列，
  `schedule()` 是空实现。界面会显示原因并指向「跑一遍」手动触发，服务端也拦。
  想开这个能力，得先让 `deploy/appliance/install.sh` 把 `worker.ts` 也拉起来。
- **定时计划的新增表单没有真机点过**。演示模式是 viewer 只读，表单不渲染。
  增删改有真库测试覆盖，但真实账号点一次仍然值得。
- **`collect_self` 只支持公众号**。插件的 `SELF_AUTO_ENTRY` 里只有 wechat 一个入口
  （它自己的注释写着「其它平台等真机验证过再加」）。放行别的平台等于排一个插件不会做的活，
  它会白跑到超时再重试三次。加平台的顺序：**先给插件加入口并真机验证，再回来放宽 `lib/browser-task/kinds.ts`**。
- **法律文本没动**。定时会在用户不在场时消耗 AI 额度，产品内已写明（定时任务区那段说明），
  但《付费协议》里「未大量消耗额度可全额退款」那条与它的关系没有澄清——
  这是产品决策，留给你定。
