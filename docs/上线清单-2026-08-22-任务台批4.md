## 一、挂起令牌从一种泛化成三种（4-A）

原来一次执行只能挂起等一件事：浏览器插件的任务。现在是三种：

| 令牌 | 等什么 | 谁来叫醒 |
|---|---|---|
| `browser:` | 插件任务（要等用户开浏览器，以小时计） | 回执落库时 |
| `workflow:` | 一条智能体流水线 | 流水线跑完时 |
| `run:` | 另一次 AI 执行（自主智能体的子运行） | 子运行到终态时 |

**加新类型时必须同时做三件事**（写在 wake.ts 顶部）：被等的那件事到终态时叫醒、
`settleIfResolved` 加一个分支、想清楚它的到期时间。只做第一件的话，进程在「落库」与
「叫醒」之间挂一次，那条运行就永远挂着了。

### run_agent 不再把整次执行钉住几十分钟

原来是 `await runWorkflow(...)` 一口气跑到底：一条十步的流水线要跑几十分钟，
而这几十分钟里**整个 AI 执行被钉在这一个工具调用上**——用户看到一条不动的任务，
超时闸到点了还会让模型以为没跑成、想再派一次（那是两次真的执行）。

现在的次序是 **建行 → 挂起（记下 runId）→ 触发执行 → 跑完叫醒**。
为此把 `runWorkflow` 拆成了 `createWorkflowRun` + `executeWorkflowRun`：
不拆的话调用方在投递前拿不到 id，只能先跑再挂——**跑完了才挂上去，那时叫醒的人早走了**。

触发用新的 `lib/workflow/kick.ts`，与 agent 那边同一个形状：
⚠️ **绝不能走 `getQueue().enqueue`**——进程内队列的 enqueue 是同步 await，
走它等于原地跑完，于是又变回「先跑后挂」。agent 那边踩过一次。

### 自愈与到期兜底

`settleIfResolved` 按前缀分派。早先它写死 `if (!token.startsWith('browser:')) return false`，
于是另外两种**完全没有自愈通道**——而 browser 那种靠插件轮询天然错开，
另外两种秒级跑完是常态，「叫醒早于挂起」这个竞态在那边是日常。

**24 小时到期兜底**：被等的那件事一崩（worker 被杀、部署重启），父运行就永久挂着——
提拔只在终态发生、到期清理只删终态、读路径自愈要有人打开页面才触发。
三条挂死就把一个工作区的并发位全堵住。定时巡检新增第三件事扫它。

界面文案也按令牌类型分写：三种等待里用户该做的事完全不同，
全印成「等你的浏览器插件」的话，等智能体的人会跑去开浏览器。

## 二、产物清单（4-B）

**确认闸管的是动作之前，产物清单管的是之后。** 两道闸互补不能互替——
预授权跑完的那些没有前一道，更需要后一道：用户授权的是「你可以建草稿」，
不是「你建的每一篇草稿我都认」。

此前「AI 改了我哪些东西」只能从步骤流水的截断文本里读：点不动、也回不去。

- 新表 `AgentArtifact`（runId / kind / refId / label）。`refId` **松引用不加外键**：
  产物表各式各样，而且产物被用户删掉之后这条记录仍有价值（「它当时做了这个，现在没了」）。
- 登记挂在 `executeCall` **唯一的咽喉**上：所有工具执行都过它，
  于是「新加的工具忘了登记产物」不会发生——它只要在 `ToolResult` 里报，就一定被记下。
- 报什么由工具自己决定（只有它知道刚写了哪一行）。已接的四个：
  `create_draft` / `run_skill` / `create_publish_plan` / `generate_image`。
- **每种产物必须有落点**（`lib/agent/artifacts.ts` 的 HREF 表）。没登记的种类返回空地址、
  界面渲染成纯文本——编一个地址出来，用户点过去看到不相干的页面，比不给链接更糟。
- 发布计划的标签写死带「还没发出去」：产物清单是扫一眼就走的地方，
  只写「发布计划」会被读成「已经发了」，而「建计划≠发出去」是这个产品的老红线。

## 三、自主智能体（批 4 后半）

`WorkflowTemplate.mode` 分两种形态，**两种都是纯数据**：

| 形态 | 是什么 | 数据形状 |
|---|---|---|
| `pipeline`（缺省） | 一串定死的步骤，跑法完全可预期 | `steps` JSON |
| `autonomous`（新增） | 给它目标和授权范围，自己安排怎么做 | 人设 + 工具白名单 + 预算 + 缺省授权档 |

自主型没有「步骤」可展开——它本身就是另一条 AI 执行循环。派它 = **起一次子运行**，
父运行挂起等它（`run:` 令牌，就是 4-A 准备好的那个）。

### 三条硬规则，每一条都是「不拦就有洞」

1. **工具白名单永远是交集**（模板要的 ∩ 用户能用的）。智能体**可以从市场装别人的**，
   以模板为准的话，装一个智能体就能越权。
2. **授权档继承但不得超过父**（`confirm_each < preauthorized < unattended`）。
   不拦的话，「派个智能体」就成了绕过自己那道确认闸的捷径：
   父是「每一步都问我」，它派一个 `defaultAuthMode='unattended'` 的智能体，那个子运行就什么都不问了。
3. **嵌套只许一层**。不拦的话一个配错的智能体能自己派自己，几层下去是指数级的额度消耗。

**预授权白名单 = 父的白名单 ∩ 子能用的，绝不按子模板重新全勾**——
那是审查抓到的一条洗白名单的三步链路：模型起草宽白名单的智能体 → 用户在预授权的父运行里派它 →
子运行重新全勾。用户从头到尾没看过那份白名单。

其它口径：
- 智能体的人设是对通用提示词的**补充不是替换**（替换掉的话「不许编数据」「Mock 不许假装执行」
  那几条硬规矩会随人设一起丢）；
- `list_agents` 按形态给不同载荷，**自主型不许印成「共 0 步」**——
  模型看到 0 步会以为是空模板而不派它，用户则以为自己配坏了；
- `roles.ts` 那一档不再说「步骤是写死的、不会临场改主意」。分界改讲成**什么时候用它**：
  预先设定好、可反复派、可挂定时（助手是现场听你说、当场授权）。

真机验过：模板想要 `unattended`、父是 `confirm_each` → 子运行落到 `confirm_each`；
父没预授权 → 子白名单为空；子运行再派被拦下并给了人话理由。

## 四、上下文折叠

原来超长时是**直接从中间成对删**——那意味着模型会忘掉自己做过什么：
一次长任务跑到后半程，前面查过的数据、建过的草稿全没了，它可能把同一件事再做一遍，
**而且是真的再做一遍，花第二次钱**。自主智能体正是长任务的来源，所以这一层随它一起上。

现在是**先折叠再删**：把要丢的那段压成一句「我在这中间做过 X、Y、Z，已经做过了不要重做」。
折叠用本地规则拼，**不调模型**——为省上下文再花一次调用不划算，而且这条路径恰恰是在
额度吃紧的长任务里走的。

+ `tests/agent/autonomous.test.ts`（24 条）。**三十三条 mutation 逐条验过会红。**

五条 mutation 抓出来的问题值得记：

1. **只测纯函数不算数**。头一版守卫全是「手工造出挂起状态再调自愈」，于是
   「run_agent 到底挂没挂起」「工作流跑完到底叫没叫醒」**一条都没验到**——
   把它们各自改坏，用例照样全绿。补了端到端才红。
2. **别 spy Prisma 的方法**。`mockRestore` 之后那个方法就不再可用，
   **后面每个用例**的写入都静默失败，表现成毫不相关的诡异失败。批 0 踩过一次，这次差点又踩。
   改成用「必定写不进去的 runId」造失败。
3. **守卫被自己的注释骗了**。「发布计划标签要说清还没发出去」那条，
   正则匹配的片段包含了写在 label 上一行的注释，而注释里也有那句话——
   把 label 改坏照样绿。剥注释后才红。
4. **纵深防御要单独验**。工具白名单收窄有两道（child-run 一道、startAgentRun 一道），
   而端到端用例验不出第二道——删掉它行为完全不变（第一道已经把活干了）。
   要用「有权限、但这次不给用」的场景才测得到。
5. **条件被前一道兜住**。「没超长就不折叠」那条用例只放了三条消息，
   而折叠还有一道「条数不足不折叠」的条件——于是把长度判断整个删掉照样绿。

另外顺手修了一个**测试互相干扰**：`kickWorkflowRun` 是 fire-and-forget 的，
而 `settleAgentKicks` 不等它——后台工作流泄漏到下一个测试文件的 beforeEach 之后才落地，
表现成一个跟本文件毫无关系的失败。
已在 **`tests/setup/per-file.ts` 全局 afterEach** 里统一收（而不是每个文件各写一遍：
新写的测试文件不会「忘了收」）。
