# 合规词库运营 & AIGC 标识覆盖

本文写给接手合规模块的人。**诚实记录现状与缺口**，不粉饰。

- 词库代码：`prisma/seed.ts`（全局三级词库）
- 检测引擎：`lib/compliance/engine.ts`
- AIGC 标识：`lib/compliance/aigc.ts`（纯函数，无 prisma 依赖）

---

## 一、词库四级设计

| 级别 | tier | 归属 | 数据来源 | 当前条数 |
|---|---|---|---|---|
| L1 法律级 | `legal` | 全局，所有平台生效 | 广告法/医疗/金融/价格法规 | 176 |
| L2 平台级 | `platform` | 全局，按 `platform` 字段只对该平台生效 | 各平台社区公约与商业化规范 | 141 |
| L3 行业级 | `industry` | 全局，所有平台生效 | 医疗/金融/电商/教育/食品行业口径 | 85 |
| L4 租户级 | `custom` | `tenantId` 非空，仅该租户生效 | 租户自建（品牌禁词、竞对名等） | 由租户维护 |

`checkText(text, platform, tenantId)` 的实际检测集 = **L1 + L2(该平台) + L3 + L4(该租户)**，
合并成一棵 DFA 后一次扫描。

### 1.1 action 三档语义

| action | 语义 | 影响 |
|---|---|---|
| `block` | 法定红线，命中即违法/平台重罚 | `riskLevel=block`；`legal` 级的 block 词会进 `hasRedline()` → UI「禁止导出」 |
| `warn` | 高风险表述，强烈建议改写 | `riskLevel=warn` |
| `suggest` | 合规但有更优写法/需备齐举证 | `riskLevel=warn`，仅提示 |

**定级原则**：`block` 只给「无歧义违法」的词。《广告法》第九条明文列举的绝对化用语只有
**国家级 / 最高级 / 最佳** 三个，其余（最好、第一、唯一、顶级……）是执法扩展口径，
且在日常中文里有大量正常用法（「最好先看看」「唯一的办法」），一律定 `warn`。
—— `legal+block` 会触发「禁止导出」硬闸，误伤代价远大于漏报。

### 1.2 suggestion 是产品价值所在

**每一条词都必须带 `suggestion`**（当前 402/402 全覆盖，其中 block 词 62/62 全覆盖）。
只拦不给替代方案的合规工具没有价值——用户会关掉它。

## 二、⚠️ 改词前必读：DFA 的实际行为

`lib/compliance/engine.ts` 的 `scan()`：

```ts
for (let i = 0; i < text.length; i++) {   // ① 从每个下标重新起跳
  let node = dfa; let j = i;
  while (j < text.length && node.children.has(text[j])) {
    node = node.children.get(text[j])!; j++;
    if (node.end && node.meta) hits.push({...});  // ② 命中后继续往下走，不 break
  }
}
```

两个后果，**加词时必须遵守**：

### 2.1 互为子串的词会重复命中

因为 ① 从每个下标起跳 + ② 命中不中断，只要「A 是 B 的**子串**」（不限于前缀），
含 B 的文本就会同时命中 A 和 B。

> 同一检测集内**禁止出现互为子串的词**，只保留较短的那个——短词天然覆盖长变体，且只命中一次。

例：只收 `稳赚`，不收 `稳赚不赔`（后者自动被前者覆盖）；只收 `带单`，不收 `老师带单`。

**特别注意：`legal` 与 `industry` 恒在同一检测集内，跨 tier 也会撞。**
本轮扩容实测揪出的 2 例都是跨 tier 撞的（`带单`(industry) ⊂ `老师带单`(legal)、
`原价`(industry) ⊂ `虚构原价`(legal)），凭肉眼 review 没看出来，是跑脚本跑出来的。
**加词后务必实测，不要只靠 review。**

### 2.2 DFA 大小写敏感、不做变体归一化

`node.children.has(text[j])` 是逐字符精确比较。因此：

- 英文词**一律小写录入**。`Giveaway` / `GIVEAWAY` 会漏检（已知缺口，见 §五）。
- 不处理全角/半角、拼音变体、火星文、字符插入（`微*信`、`威 信`）。
  谐音变体只能靠**穷举录入**（已收 `威信`/`薇信`/`徽信`/`vx`/`V信`）——这是治标。
  对抗性变体绕过是本地词库的固有上限，只能靠 §四 的语义复检 + 云审核兜底。

### 2.3 已刻意移除的高误报词

扩容时删掉了几个「爆量误报」的裸词，**不要加回来**：

| 词 | 为什么删 | 替代方案 |
|---|---|---|
| `第一` | 「第一次 / 第一步 / 第一天 / 第一时间」全中，且原为 `block` → 直接禁止导出 | 改收 `全国第一`/`行业第一`/`销量第一`/`排名第一`/`第一品牌`/`第一名` |
| `特效` | 本产品面向短视频创作者，「加个特效」是高频正常表达 | 改收 `特效药` |
| `稳赚不赔` / `一夜暴富` | 与 `稳赚` / `暴富` 互为子串，重复命中 | 由短词覆盖 |
| `保本保息` | 与 `保本` 互为子串 | 由 `保本` 覆盖 |

## 三、月度版本化更新流程

`SensitiveWord.version` 字段（默认 `'2026.07'`），由 `prisma/seed.ts` 顶部的
`WORDLIST_VERSION` 常量统一写入，**整库按月发版**。

### 3.1 流程

1. **收集**（每月最后一周）
   - 监管侧：市场监管总局处罚公告、网信办通报、新规原文。
   - 平台侧：各平台社区公约/商业化规范的变更日志。
   - 业务侧：租户 L4 自定义词中的高频词（多个租户都在加的词 → 考虑升级为全局 L3）；
     线上 `ComplianceCheck` 表里 `riskLevel=block` 但用户仍强行发布的记录 → 疑似误报，考虑降级。
2. **改 `prisma/seed.ts`**：改词 + 把 `WORDLIST_VERSION` 递增为新月份（如 `'2026.08'`）。
3. **跑体检**（**不可跳过**）：见 §3.2。
4. **发布**：`npm run db:seed`（当前 seed 是全量重建，见 §3.3 的缺口）。
5. **回滚**：`version` 字段保留了发版号，出问题时可按 version 定位并回退到上一版 seed。

### 3.2 体检脚本（当前缺失，需补）

每次改词后必须验证的四项：

1. **子串冲突**：对 6 个平台各自的检测集，两两检查 `b.includes(a)`，必须 0 冲突。
2. **误报体检**：一组正常创作者文案，断言不产生 `block`/`warn`。
3. **召回体检**：一组违规文案，断言命中且命中数不爆炸。
4. **suggestion 覆盖**：所有 `block` 词必须带 `suggestion`。

> **缺口**：本轮是用一次性临时脚本跑的，跑完即删，**没有沉淀成仓库里的常驻测试**。
> 应把上述四项固化进 `scripts/verify-flows.ts` 或独立的 `scripts/verify-wordlist.ts`，
> 纳入 CI。否则下个月改词的人会重蹈「靠肉眼 review 漏掉跨 tier 子串冲突」的覆辙。

### 3.3 seed 是全量重建，不是增量升级

`prisma/seed.ts` 开头 `deleteMany()` 清空全部数据后重灌。这在**生产环境不可用**：

- 会清空租户的 L4 自定义词（`tier='custom'`）和所有业务数据。
- 生产的词库更新必须改成**只针对全局三级词的 upsert**：
  按 `(word, tier, platform)` upsert，写入新 `version`，
  并把本次未出现、且 `version` 仍是旧版的全局词置 `enabled=false`（软删除，保留可回滚）。
- 这个增量升级脚本**尚未实现**。

## 四、商业审核 API 兜底（必须接，本地词库不够）

### 4.1 为什么必须接

**涉政类词库本项目刻意不收录。** 自己列既不完整也不专业，漏一个的代价（下架/封站/约谈）
远高于全部不做。这类判定必须交给持牌的商业审核服务。同理，本地 DFA 也搞不定：

- 语义级违规（不含敏感词但整体违规）
- 对抗性变体（谐音、拆字、字符插入、emoji 替换、图片嵌字）
- 涉政、涉黄、涉暴恐、未成年人保护等需要专业判定 + 持续更新的类目

**定位**：本地 DFA 是**免费、毫秒级的初筛**，不是终审。云审核是终审。

### 4.2 三层检测架构（目标态）

```
L1 本地 DFA（已实现，免费/毫秒级）
  → L2 LLM 语义复检（已有 llmComplete 通道，未接入合规链路）
    → L3 云审核终审（未实现）—— 涉政/涉黄/对抗变体
```

### 4.3 接入点

**代码位置：`lib/compliance/engine.ts` 的 `checkText()`**。当前实现：

```ts
const dfa = buildDfa(words);
const hits = scan(text, dfa);
let riskLevel = ...;
return { hits, riskLevel, platform };   // ← 在此之后追加云审核
```

建议在 `return` 前插入一个 `cloudModerate(text)`，并遵守项目铁律
**「配置即激活，不配就优雅回退」**：未配 key 时直接返回 `null`，dev 态零基础设施照常可跑。

```ts
// 伪代码，放在 checkText 的 return 之前
const cloud = await cloudModerate(text);          // 未配 key → null
if (cloud?.riskLevel === 'block') riskLevel = 'block';
return { hits, riskLevel, platform, cloud };
```

`cloudModerate` 建议新建 `lib/compliance/cloud.ts`，按 vendor 分支：

| 厂商 | 服务 | 接口 | 需要的环境变量 |
|---|---|---|---|
| 阿里云 | 内容安全 Green | `TextModerationPlus` (`green-cip` endpoint)，`service=comment_detection` / `chat_detection` | `BEACON_ALIYUN_AK` / `BEACON_ALIYUN_SK` / `BEACON_ALIYUN_REGION` |
| 腾讯云 | 天御 TMS | `TextModeration` (`tms.tencentcloudapi.com`) | `BEACON_TENCENT_SECRET_ID` / `BEACON_TENCENT_SECRET_KEY` |

两家都返回「建议动作（通过/审核/拦截）+ 命中标签（涉政/涉黄/广告…）」，
映射到本项目的 `riskLevel`（pass/warn/block）即可。

**注意**：两家 SDK 都需要额外依赖，签名算法（阿里云 ROA/RPC、腾讯云 TC3-HMAC-SHA256）
用 `node:crypto` 手写 fetch 调用即可，不必引 SDK（符合项目「优先 Node 内置」的约定）。

**兜底策略**：云审核超时/失败时**不可**直接放行也**不可**直接拦截——
建议降级为 `warn` 并记录，由人工复核，避免第三方抖动阻断全站发布。

## 五、AIGC 标识：覆盖现状与缺口

法规依据：《人工智能生成合成内容标识办法》（2025-09-01 施行）+ 强制性国标 **GB 45438-2025**。

### 5.1 法条核对结论

| 条款 | 要求 | 本项目 |
|---|---|---|
| 第四条(一) | 文本类在**起始、末尾或中间适当位置**添加文字提示 | ✅ 追加到文末，位置合规 |
| 第四条末款 | 提供**下载、复制、导出**功能时，应当确保**文件中**含显式标识 | ⚠️ 见 5.3 |
| 第五条 | 在**文件元数据**中添加隐式标识 | ❌ 见 5.4 |
| 第七条 | 任何组织和个人不得恶意删除、篡改、伪造、隐匿标识 | ✅ 已在导出按钮 title 明示 |
| GB 45438-2025 | 文本显式标识须**同时含「人工智能/AI」与「生成/合成」两类关键词** | ✅ 见下 |

**标识文案**：原为 `本内容由 AI 生成`，含「AI」+「生成」，**本身即满足国标关键词要求**。
本轮改为 **`本内容由人工智能生成`**，理由是「人工智能」是《办法》与国标的正式用语，
更贴近监管口径；两者都合规，属于稳妥性优化而非纠错。
`hasAigcLabel` 同时兼容旧文案，历史内容不会被重复打标。

> ⚠️ 注意「**复制**」是第四条明列的出口，与下载/导出同等义务——这点极易被漏。

### 5.2 `hasAigcLabel` 的隐患已修复

**旧实现**：

```ts
return text.includes(AIGC_LABEL) || /本内容(由|经)\s*AI\s*(生成|辅助)/.test(text)
       || text.includes('AI 生成');   // ← 隐患
```

`text.includes('AI 生成')` 过于宽松：正文里随口提一句「**AI 生成**的图片很火」就被判为已带标识，
导致 `ensureAigcLabel` 跳过追加 → **真正的标识不被添加 → 直接违反第四条**。
这是「合规检查反而导致不合规」的典型。

**新实现**：按行拆分，剥离装饰符（`——`/`【】`/括号/Markdown 强调）后做**整行锚定匹配**——
标识必须**整行即标识**，行尾不得再续正文。

```ts
const AIGC_LABEL_LINE =
  /^(本|该|此)?\s*(内容|文本|文章|文案|图片|视频|音频)?\s*(由|系|为|经)?\s*(人工智能|AI)\s*(技术)?\s*(辅助)?\s*(生成|合成|生成合成)\s*(内容)?$/i;
```

`AI 生成的图片很火` 因为「生成」后面还有「的图片很火」，整行不匹配 → 正确判定为「无标识」。

### 5.3 出口覆盖矩阵

| 出口 | 位置 | 显式标识 | 隐式标识 |
|---|---|---|---|
| 导出 PPTX/DOCX/PDF | `studio/actions.ts:actExportDeliverable` → `lib/llm/skills.ts` | ✅ | ❌ |
| 复制正文（创作工坊） | `studio/page.tsx` → `components/CopyText.tsx` | ✅ 本轮补上 | ⚠️ 仅 text/html flavor |
| 复制内容（数据回流） | `data/page.tsx` → `components/CopyText.tsx` | ✅ 本轮补上 | ⚠️ 仅 text/html flavor |

`CopyText` 现在**默认**加标识（`aigc` 默认 `true`），非 AI 内容可显式传 `aigc={false}` 关闭。
默认开是刻意的：漏标的代价远大于多标。这样 `studio/page.tsx` / `data/page.tsx` 无需改动即合规。

**非出口**（不需要标识，属于「交互场景界面」内的编辑态）：
`Rewriter.tsx` / `Checker.tsx` / `Chat.tsx` 的 textarea —— 内容仍在平台内，
用户要拿走必须经过上面三个出口。

### 5.4 ❌ 缺口：隐式标识（第五条）基本没做

第五条要求在**文件元数据**中写入 `{"AIGC":{"Label":"1","ContentProducer":"...","ProduceID":"..."}}`。

**已做**：`lib/compliance/aigc.ts` 提供了载荷构造器 `buildAigcMetadata()` / `aigcMetadataJson()`，
字段符合 GB 45438-2025。复制出口通过 `aigcHtmlPayload()` 在剪贴板 `text/html` flavor 里
挂了 `<!--{AIGC:...}-->` + `<meta name="aigc-metadata">`，粘贴进 Word/WPS/公众号编辑器时会带走。

**没做（真实缺口）**：

1. **导出的 PPTX/DOCX/PDF 文件元数据里没有隐式标识**——这是**硬缺口**。
   文件字节由 Anthropic Agent Skill 在容器内生成后回传，要写元数据必须在
   `actExportDeliverable` 拿到 Buffer 后二次改写：
   - DOCX/PPTX 是 OOXML(zip)：需重写 `docProps/core.xml` 的 `<dc:description>`，**需要 zip 库**（如 `jszip`）。
   - PDF：需写 Info 字典或 XMP，**需要 PDF 库**（如 `pdf-lib`）。
   两者都要加依赖，本轮未做。**上线面向中国公众的正式功能前必须补。**
2. **纯文本复制到只接受 `text/plain` 的场景**（如记事本、部分编辑器）只有显式标识，无隐式标识。
   这是剪贴板机制的固有限制，可接受——显式标识仍在。
3. **显式标识依赖 LLM「保留」**：`lib/llm/skills.ts` 是把已标注文本连同
   「要求：在结尾保留该声明」的提示词一起交给 Skill 生成文件，**模型有可能把它丢掉**。
   第四条要求的是「**确保**」，提示词不构成「确保」。
   `studio/actions.ts` 已在出口层自行调 `ensureAigcLabel` 兜底（幂等，不会叠加），
   但**生成后的二进制文件没有校验回环**——无法确认标识真的在文件里。
   彻底的修法是 §5.4.1 的元数据注入 + 文本层校验，或改为服务端自己排版而非交给 LLM。
4. **数字水印**（第五条鼓励项，非强制）：未做。
5. **`ContentProducer` 在复制出口取不到服务端环境变量**：Next 只向客户端包注入 `NEXT_PUBLIC_*`，
   故复制路径要让 producer 生效必须配 **`NEXT_PUBLIC_AIGC_PRODUCER`**，
   否则回退为默认值 `烽火台`。导出路径读 `BEACON_AIGC_PRODUCER` 即可。
6. **`ProduceID` 未持久化**：复制时用 `crypto.randomUUID()` 现生成，没有落库。
   第五条的「内容编号」应当可追溯，理想做法是与 `DraftVersion.id` 绑定并记录。

### 5.5 备案提示

`lib/llm/skills.ts` 已注明：Agent Skills 走 Anthropic 海外端点，
面向中国公众的正式发布内容默认不走此通道（PRD §10.5）。
AIGC 标识义务的主体是**服务提供者**——即本项目，不是模型厂商，标识必须由本项目自己加。
