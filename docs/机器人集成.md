# 机器人集成（飞书出站推送 + 入站 ChatOps 收录引擎）

一句话：**出站** = 平台把热点/选题/合规/学习小结推到飞书群；**入站** = 在群里发链接/文本收录成
选题、发命令驱动内容引擎。provider 可插拔（feishu 先落地，钉钉/企微/telegram 加 adapter 即复用）。

代码：`lib/bot/*`、`app/api/bot/feishu/events/[key]/route.ts`、设置页 `app/(app)/settings/BotIntegrationCard.tsx`。
数据：`BotIntegration` 表（密钥经 `lib/crypto` 加密进 `secretsEnc`，明文不落库）。

## 红线（改代码前先读）

- **收录只进候选池，绝不自动发布**。命令只做「收录/查询/采集」，生成走既有管线时仍**全程过合规**。
- **密钥永不回显**：`secretsEnc` 加密存储，设置页表单留空=保持原值。
- **入站三道闸**：① 路径 `key`(app_id) 命中某启用集成 → ② Verification Token 相符 → ③ 开了加密则
  `X-Lark-Signature` 验签。飞书服务器不带登录 cookie，故 `/api/bot` 在 middleware PUBLIC_PATHS 白名单里，靠上述自守卫。
- **inboundKey(app_id) 全局唯一**：一个飞书应用只能绑一个工作区，防串号。

## 一、出站推送（真·一键）

面向用户：设置 → 机器人 → 配置飞书机器人 → 粘贴**群自定义机器人 webhook**（可选签名密钥）→ 勾选要推的事件 → 保存 → 测试发送。

1. 飞书群 → 设置 → 群机器人 → 添加「自定义机器人」→ 拿到 webhook（形如 `https://open.feishu.cn/open-apis/bot/v2/hook/xxxx`）。
   若开了「签名校验」，把密钥也填进来。
2. 勾选推送事件：每日选题推荐 / 热点刷新 / 竞对待刷新 / 合规拦截告警 / 学习小结。
3. 「测试发送」验证接通。

推送触发点（**所有 cron 的时区口径是北京时间**，见 `lib/jobs/schedule-config.ts` 的 `SCHEDULE_TZ`；
容器里没有 TZ、系统时间是 UTC，不显式指定时区的话每一条都会晚 8 小时打出去）：
- `daily_recommend` job（每日 05:00）生成推荐 + 写站内信，**不直接推群**。
- `push_daily_brief` job（每 10 分钟扫一遍）把晨报推到**这一跳到点**的机器人 → 群。
  到点与否按每个机器人自己的 `pushSchedule`（设置页「每日定时推送时间」，默认 09:00，可填多个如 `09:00,18:00`）判定，
  判定逻辑见 `lib/bot/push-window.ts`：窗口左开右闭，一天只命中一次，且绝不早于设定时刻推。
  生成与推送分开是刻意的——推荐要趁早算好（热点有时效），但打扰用户得按他自己定的钟点。
- `optimize_memory` job（每日 05:30）优化记忆后推「学习小结」。
- 其余事件（hot_ready / refresh_reminder / compliance_alert）已在 `PUSH_EVENTS` 注册，
  在对应业务点调用 `pushEvent(workspaceId, event, message)` 即可接上（旁路，自兜底不 throw）。

## 二、入站 ChatOps（收录 + 命令）

面向用户：设置 → 机器人 → 展开「入站 ChatOps」→ 建飞书**自建应用**、填 App ID/Secret/校验串、把回调地址粘进飞书。

1. 飞书开放平台建**自建应用** → 拿 App ID / App Secret。
2. 开启「事件订阅」：
   - 回调地址填 `https://<你的域名>/api/bot/feishu/events/<App ID>`（设置页会按你填的 App ID 自动拼好）。
   - 复制 **Verification Token**（必填）、**Encrypt Key**（开了加密才填）到设置页。
   - 飞书会打一次 URL 校验握手，端点回 `challenge` 即通过。
   - 订阅事件 `im.message.receive_v1`（接收消息）。
3. 权限：给应用「接收消息」「以应用身份发消息」权限（回执用 `tenant_access_token` 发文本）。
4. 把机器人加进群，@它或私聊发消息即可。

命令（`lib/bot/router.ts`）：

| 输入 | 动作 |
|---|---|
| @机器人 + 问句 | 自由对话（`lib/bot/chat.ts`）。注入账号上下文（人设/指纹/基线/受众/记忆），带会话多轮上下文 |
| 发文章链接 / 粘长正文(≥300字) | 剪藏（`lib/clip`）：抓正文 → 摘要 + 要点 + 结合账号的用处 → 存 InspirationItem |
| `/存` `/剪藏` | 显式剪藏 |
| `/竞对 [名字]` | 列监控中竞对的近期高热作品（带链接，接着可拆） |
| `/拆解 <链接>` | 强制走 rival 模式（它凭什么跑起来 + 能借鉴什么） |
| 直接发短文本 | 收录成选题候选（挂本群绑定账号，无绑定则工作区首个活跃账号，去重） |
| 直接发链接 | 竞对主页链接→加入竞对监控；其它链接→收录成选题 |
| `/分析 [账号名]` | 账号体检（`lib/bot/analyze.ts`）：事实包 + LLM 点评 |
| `/问 <问题>` | 显式对话（绕开「像不像选题」的判断） |
| `/账号 [名字]` | 看/切换本群当前账号（存 `BotConversation.accountId`） |
| `/热点` | 返回当前热榜 Top8 |
| `/选题 关键词` | 关键词收录成选题候选 |
| `/采集 竞对主页URL` | 加入竞对监控并试采一次 |
| `/优化` | 触发一次记忆学习优化，回小结 |
| `/重置` | 清空本会话对话上下文（账号绑定保留） |
| `/帮助` | 指令说明 |

**对话 vs 收录怎么分**（`lib/bot/intent.ts`）：斜杠命令 → 确定性短语 → `looksLikeChat`（含人称的求助句式）
→ LLM 分类 → 兜底 `ingest`。分界的取舍是刻意的：「我这条为什么没火」是提问，
「为什么年轻人不买房了？」是个好标题，后者交给 LLM，LLM 也拿不准就收录（无副作用）。

**群里的 @ 闸**（`feishuPassesMentionGate` + `feishuMentionsBot`）：群消息没有任何 @ 直接忽略；
有 @ 时再用 `bot/v3/info` 拿机器人 open_id 核对「@ 的是不是我」（进程内缓存 1h）。
默认权限下飞书本就只在被 @ 时推事件，这道闸是为了应用申请了「接收群聊中所有消息」的情况——
不设它机器人会对群里每句话都回一遍。取不到 open_id 时放行（宁可多答一句，不能因网络抖动装死）。

**会话上下文**存在 `BotConversation`（`(integrationId, chatId)` 唯一）：最近 8 条、单条截断 800 字、
静默 1 小时即视为新会话。按会话存而不是按人存——群里 A 问「那第二条呢」接的是 B 刚才那句。

## 文章剪藏（`lib/clip`）

抓取统一走 `lib/web/fetch` 的 `safeFetch`（SSRF 护栏 + 逐跳复验重定向 + 2MB/10s 上限 + 编码兜底），
**不要再写第二份抓取**。正文提取在 `lib/clip/extract.ts`：站点专属容器（公众号 `#js_content`）→ 语义容器
（`<article>`/`<main>`）→ 挑最大文本块；**站点容器命中就照单全收**，短文也不退回整页（退回=把导航和二维码当正文）。

两种读法同一套产出：`note` 学习笔记（默认）、`rival` 爆款拆解。发的链接命中本工作区监控中的竞对作品时
自动切 `rival`（`rivalOfUrl`：先按 CrawledPost.url 精确匹配，再按 handle 兜底）。

⚠️ **存他人正文的三条护栏**（缺一条这功能就成洗稿工具）：① 只落用户自己工作区；
② **绝不进生成语料池**——原句样本只取 Material(sample)/PublishRecord/DraftVersion(human)，
`tests/clip/clip.test.ts` 里那条 🔒 用例钉死；③ 回执与页面都标注来源与「别直接复用其文字」。

## 入站命令白名单（`BotIntegration.allowCommands`）

机器人装在群里，群里可能有实习生、外包、客户。`/分析` 会把粉丝数与播放量摊在群消息里、
`/问` 会烧租户的 AI 配额——放不放开由**管理员**决定（设置页「群里允许哪些操作」，权限 `byok.manage`，
与密钥同级，仅 owner/admin）。目录见 `BOT_COMMANDS`（`lib/bot/types.ts`），带 `warn` 的项在设置页高亮。

⚠️ **空数组 = 从未配置 = 默认全开**，不是全关。线上老数据全是 `"[]"`，把空当成全关会让所有已装机器人
在一次发版后集体哑掉且不报错。管理员保存时**永远补写一个 `help`**，所以「配过但全关」是 `["help"]`，
与「没配过」区分得开。`help` 恒开——全关时机器人至少还能自报家门，不做一个不响的黑箱。

白名单在 `handleInbound` 内部查库读取（不由三个 endpoint 传参）：**传参会漏，漏了就是白名单被静默绕过**。
斜杠命令与自然语言意图走同一道闸——只拦斜杠、说人话就放行，等于没拦。

**快速 ack**：端点验签/解析后立即回 200（飞书要求 <3s，超时会重推），实际处理 + 回复走后台
（常驻 Node 进程安全）。所有操作幂等（收录去重 / 订阅 upsert / 查询无副作用），偶发重推不会重复入库。

## 扩展到其它平台

`BOT_PROVIDERS` 里把目标平台 `supported` 打开，实现一个 adapter（出站 `sendXxxWebhook`、入站验签/解析），
在 `lib/bot/index.ts` 的 `sendVia` 和一个 `/api/bot/<provider>/events` 端点接上即可，数据层/设置页无需改。
