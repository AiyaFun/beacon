## 一、并发上限与排队

每个工作区同时最多 **3 个** 运行在真的跑（`MAX_CONCURRENT_RUNS`），队列最长 **10 条**。

- **上限只数 `running`**。挂起的那些（等确认 / 等插件 / 等额度）不占名额——数它们会死锁：
  三个运行都停在「等你确认」，用户想再派一个却被拦住，而他要确认的那三个恰恰要他先腾出手来。
- **有人排队时新来的一律排队尾**，即使这一刻恰好有空位。否则「先到的还在排、后到的插队先跑」。
- **队排满了当场拒绝**而不是继续收：一个手滑连点二十次的用户会给自己排出一条跑一整天的队，
  而他多半只想要第一条的结果。
- **竞态明文容忍超发 1–2 条**。这是「先数后建」，两个请求可能同时数到 2<3 于是双双开跑。
  租约保证没有任何一条运行会被跑两遍，超出的那一两条只是让额度消耗快一点点；
  而为它上分布式锁要引入一整套新的失败模式（Redis 不可用时是拦死所有人还是放行所有人？）。

**提拔挂在 `transition()` 上**（批 0 建的那个咽喉）：一个运行离开 `running` 就腾出名额，
叫排最久的那个上来，一次只放一个。判据是「**从 running 走掉了**」——
`queued → cancelled` 不算让位（它本来就没在跑），跟着提拔会让并发悄悄超上限。

**定时巡检兜底**：提拔链路有一处断点——**进程被杀时不会发生任何状态迁移**，
三个 running 随进程消失，队列里的就永远等着一个不会到来的「让位」。`tick_agent_runs` 补这一刀。

**排太久的会被清**：`queued` 不是终态，90 天到期清理（只删 done/failed/cancelled）碰不到它。
超过 7 天没轮上的自动取消**并通知用户**——系统替他取消的事，不说一声他就是在等一个永远不会跑的任务。

## 二、通知：跑完了叫我一声

此前 AI 执行**一次通知都不发**（`lib/agent` 全目录零 `notify` 调用），而界面明确告诉用户
「可以关掉这一页去做别的」——那句话的真实含义是「这件事从此没有任何东西会提醒你」。

五个状态各发一条：`awaiting_confirm` / `waiting_browser` / `waiting_quota` / `done` / `failed`。
正常推进（开跑、排队）不吵人；**用户自己点的终止也不发**（他当然知道）。

- **去重键 = `runId + 状态 + episode`**。只按 (runId, status) 去重的话，将来「追问 → 同一条运行
  再跑一遍 → 又跑完了」那次会静默——而追问的人正是最想知道结果的那个。`episode` 现在恒为 0，
  批 3 做追问时才会递增；**先建在这里是为了让去重键从一开始就是对的**。
- **通知写明发起人**（「等 张三 确认一步操作」）。`Notification` 表没有 `memberId`、红点是工作区级
  人人可见，而「确认」只有发起人点得动——第二人称会让同事去点一个必定报错的按钮。
- 通知是旁路：发不出去只是没通知，绝不影响执行本身（有守卫）。

## 三、AI 执行走独立队列

`run_agent_loop` 从主队列 `beacon-jobs` 挪到 `beacon-agent`，worker 起两个消费者
（并发分别由 `BEACON_WORKER_CONCURRENCY` 与 `BEACON_AGENT_CONCURRENCY` 控制，默认都是 4）。

**为什么必须分开**：一次 AI 执行的 loop 会占住一个槽几十分钟（十几轮模型调用，中间还夹着
8 分钟的出图、20 分钟的智能体）。四个用户同时派活，热榜采集、定时智能体、清理、发布回流
就全部排在它们后面——**一个人用 AI 助手，整个平台的定时任务停摆**。

⚠️ 部署后确认 worker 日志里有两条队列：`beacon-jobs(并发 4) + beacon-agent(并发 4)`。

## 四、界面口径

- `queued` 与 `waiting_quota` 都归**「进行中」桶**而不是「等你处理」：那一桶的标签写着
  「等你处理」，而这两种情况用户什么也做不了、也不用做。到底在等什么由 detail 说清楚
  （「在排队，等前面的任务跑完就自动开始」）。
- **活动条的「等你处理」只对自己发起的那条说**。这一页是工作区级的，同事的运行也在列（刻意的），
  但 AI 执行的确认只有发起人点得动——同事那条显示「等 李四」。判定在服务端做完，
  首屏快照与 15 秒轮询**两个数据源都要判**（只判一处的话，第一眼是对的、15 秒后变了）。
- 徽章算法抽成纯函数 `lib/runs/badge.ts`。⚠️ **那个文件必须零依赖**：`lib/runs/index.ts` 引了
  prisma，客户端组件 import 它会把 prisma 打进浏览器包——tsc 全绿、单测全绿，
  **只有真机打开页面才 Build Error**（同 `lib/shell.ts` 引 `next/headers` 那次）。
