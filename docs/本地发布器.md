# 本地发布器（整机版 / 私有化版）

> 一句话：在装了烽火台的那台机器上跑一个**常驻登录的浏览器**，替你打开创作后台把内容填好。
> SaaS 版没有这条路——服务端在机房，够不到你的浏览器。

## 它与另外两条路的分工

| 路 | 谁在动手 | 适用 |
|---|---|---|
| 官方接口直发 | 服务端调平台接口 | 公众号、微博（**只有这两家对个人开放**） |
| 浏览器插件 | 你自己电脑上的 Chrome | 任何形态，用户当场点「填充」 |
| **本地发布器** | 装机那台机器上的 Playwright 浏览器 | **整机版 / 私有化版**，无人值守也能填 |

三条路共用同一批发布任务与回执接口（`/api/publish/tasks`、`/api/publish/receipt`），
所以在「发布中心」看到的状态是一致的，不会出现「插件说填好了、发布器又填一遍」。

## 装一次

```bash
# 在装了烽火台的那台机器上（Mac mini / Windows 均可）
cd /path/to/beacon
npm i -D playwright
npx playwright install chromium
```

> Playwright **不在 package.json 的依赖里**：SaaS 的 docker 镜像用不上它，装进去白白多几百 MB。

## 跑起来

```bash
export BEACON_PUBLISHER_HOST="http://localhost:3000"     # 烽火台地址
export BEACON_PUBLISHER_TOKEN="beacon_xxx"               # 「接入与密钥 · 插件采集令牌」为这台机器签发
npm run publisher
```

第一次会弹出一个浏览器窗口，**在里面把要发的平台各登录一次**（扫码/验证码都由你本人完成）。
登录态存在 `.publisher-profile/`（可用 `BEACON_PUBLISHER_PROFILE` 改路径），
**只在这台机器上，不上传、不外发**。

## 代点发布（默认关）

```bash
export BEACON_PUBLISHER_AUTO_CLICK=1   # 填完自动点发布按钮
```

不设这个变量就只填不点，由你自己检查后再发。开之前请知悉：

- 各平台创作者协议普遍不欢迎自动化发布，出问题（限流/封号）平台通常没有申诉渠道；
- **发布不可撤销**；
- 即使开了，仍有三道闸：只有**标题与正文都填成功**才会去点；只认文字为「发布/发表」
  且不含「草稿/预览/定时/删除」的可见按钮，**认不出就不点**；点完报 `published` 但
  **不带作品链接**（拿不到），要你回发布中心补链接才能开始回流数据。

## 它明确不做的事

- **不做云端 cookie 托管**：登录态不离开这台机器，服务端一个字节都不存。
- **不绕过登录/风控/验证码**：它就是一个你自己开着、自己登录过的浏览器。
- **不无人值守批量刷号**：任务串行处理，一次一条。

## 选择器没真机校准

`lib/publish/selectors.ts` 是发布页选择器的**唯一真相源**（插件与本地发布器共用，
`tests/publish/selectors-sync.test.ts` 钉死两份一致）。这批选择器**尚未在真机上校准**，
填不进去是预期内的情况——发布器会如实报 `failed` 并写明原因，不会假装填好了。
校准后请只改 `lib/publish/selectors.ts`，插件那份跟着同步。
