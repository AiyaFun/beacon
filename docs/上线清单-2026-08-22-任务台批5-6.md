## 批 5：一键任务与定时派发

### 一、为什么值得存一张卡

派活现在要打一段字、选一个智能体、勾一次授权范围，而绝大多数人反复要的就是那么三五件事。
每次重打不只是麻烦——**授权范围每次都要重勾，勾错了没人拦得住**。

新表 `TaskPreset`（目标 + 让谁干 + 授权到什么程度）。点一下开派发弹层，
能看清授权范围、也能临时改这次的目标（不动那张卡本身）。
管理区挂在 `/workflows#presets`（**零新路由**——定时也在那一页，
「配一次、以后一键或到点自动跑」本来就是同一件事的两种触发）。

### 二、无人值守只能由定时派

卡上可以存这个档，但**只有 `origin='schedule'` 才放行**。
用户在页面上点那张卡的时候人就在跟前，没有理由不问他。

⚠️ 实现时先写成了「preset 也放行」，是守卫当场抓住的——
那等于「存一张无人值守的卡，然后手点」就绕过了确认闸。

保存那一层也拦一道：卡上存着一个「无人值守」而实际从不生效，用户会以为自己配好了。

### 三、连败自停闸必须搬家

这是这一批**最容易漏的一件**：闸原来靠 `await runWorkflow` 的**同步返回值**记账，
而派一条 AI 执行是**异步**的——派发那一刻它还没跑，拿不到结局。
照抄旧写法的话 `failStreak` 永远不累加，**一条配坏的定时会每天准点烧配额且永不自动停用**
（那正是这道闸存在的理由）。

修法：`AgentRun` 加 `scheduledAgentId`，在**状态迁移那个咽喉**（批 0 建的 `transition`）
到终态时回写。额度用完不累加（与流水线那边同一个口径：那是「今天没轮到」，不是「配错了」）。

### 四、调度分两条路

`ScheduledAgent.targetKind`：`workflow`（旧行为，同步跑完）| `task`（派一条预设任务，异步）。
`templateId` 随之改可空——不改的话 `targetKind='task'` 那种根本建不了行。

⚠️ **派发那一刻刻意不记成功**：它才刚开始跑。记 `done` 的话，
一条每次都跑失败的定时会永远显示「上次跑成功了」。

定时现在能指两种东西，「这条计划叫什么」抽成了 `scheduleTargetLabel`
（设置页、跑动记录、喂给模型的 `list_schedules` 三处共用，各写各的迟早对不上），
且被删了要如实说而不是印一个空名字。

## 批 6：打磨

### 一、这次花了多少

`LlmCallLog.runId` 批 0 就加了，到这里才有读它的地方。任务视图显示
「这次用了 N 次 AI 调用 · 约 X.Xk tokens」。

**按 token 而不只按次数**：长任务后段每次调用都背着接近上限的对话，
单次成本是短调用的十倍量级——只报次数会让用户以为「10 次的任务只有 1 次的十倍贵」。
Mock 调用不算（它不花钱）。

### 二、对外调用面补上终止

`DELETE /api/v1/runs/<id>`。**可以给终止，但永远不给确认**——两者性质不同：

- 确认 = 替用户同意一件他没看过的事。调用方常常是另一个模型，模型 A 起草、模型 B 代签，
  那条规矩就等于没有。
- 终止 = **不做**。它不产生任何新的写操作，最坏是白跑一趟。

没有它的话，一次派错的活只能等它跑完或去网页上点——而对外调用面的使用场景
（脚本、CI、别的系统）恰恰是没人守着网页的那种。走的是同一个 `cancelAgentRun`（归属校验在它里面）。

### 三、红点不该为一件我推不动的事亮起来

`Notification` 加 `memberId`（null = 人人可见，旧行为）。AI 执行的通知点名给发起人——
「等你确认」只有他点得动，推给同事就是让他看着一件自己做不了的事。
顶栏的**红点与列表两处都要按人过滤**（只过滤一处会让两者对不上，更奇怪）。

## 守卫

新增 `tests/agent/preset.test.ts`（19 条）+ `tests/agent/polish.test.ts`（11 条）。
**二十二条 mutation 逐条验过会红。**

两条 mutation 抓出来的问题：

1. **守卫只验「文件里有这个字符串」**。「调度按 targetKind 分派」那条扫的是源码，
   而同一文件的 `nameOf` 里也有一份同样的字符串——把真正的分派整个删掉照样绿。
   已改成行为测试（造一条到点的 task 型定时，验它派出的是 `AgentRun` 而不是 `WorkflowRun`）。
2. **`actSavePreset` 根本没有守卫**（它是 server action，行为测试没覆盖）。

### 顺带修掉一个间歇性变红的老守卫

`tests/agent/transition.test.ts` 的「模型正在想的时候点终止」在全量里偶尔红
（六次单跑红一次）。真因是**测试自身的竞态**：`startAgentRun` 里的 kick 是异步的，
它可能在 `runId = started.runId` **赋值之前**就调到了模型，那一下取消根本没触发。
改成在回调里现查「当前正在跑的那条」。

**一个偶尔红的守卫最坏的地方是——人会开始忽略它。**
