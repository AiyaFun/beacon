## 一、为什么是一张表，不是 AgentRun 上的一个 JSON 列

这一列会有**两个写入方**：web 请求（用户打字）与后台循环（消费掉它）。
JSON 列只能读-改-写，两边同时来必丢话，而且丢得无声无息——用户打完字，那句话就没了。
insert-only 的子表天然没有这个问题：追加是纯 INSERT，消费是按 id 标记。
顺带得到一件事：附言也进了审计流水，「AI 为什么这么做」能追到是谁在中途说了什么。

**排干先标记再返回**：标记失败就当没读到（用户那句话还在，下一轮再来）；
反过来先返回后标记的话，中间崩一次就会把同一句话送两遍。

## 二、三个消费点，缺一个就丢话

| 时机 | 为什么必须有 |
|---|---|
| 每轮开头 | 正常情况下的消费点 |
| 转「等你确认」之前 | 用户在「正要弹确认卡」那一刻打的字会一直悬着——他看着确认卡，以为补充的要求已经被听到了 |
| **到终态之前** | 最容易漏的一个。「就快跑完时想起还有件事」恰恰是最常见的追问时机，而那时模型已经把话说出口了 |

第三个的处理是：**不许收工**，带着新要求再想一轮。

## 三、跑完之后接着说一句：同一条运行继续

**为什么必须是同一条**：新开一条的话，它不知道前面查过什么、建过什么草稿——
用户说「刚才那篇标题再改改」，新运行只能从头再查一遍，还很可能得出不一样的结论。
上下文本身就是这次执行最值钱的东西。

续跑时：
- **预算再给一段**（不给的话它一睁眼就撞上「额度用完」的收尾轮）；
- **轮数从头算**（防打转那道闸是针对一段连续推理的，新的一段该重新计数）；
- **激活段 +1** —— 通知的去重键带着它（批 1 建的），不然「第二次跑完」会被当成重复而静默，
  而追问的人正是最想知道结果的那个；
- **清掉上次的错误**（续跑成功后不该还挂着上次的红字）。

失败的那条也能接着跑——**「接着跑」同时是失败任务的重试入口**，不用重新口述一遍目标。

## 四、三个出口，语义不许混

| 按钮 | 做什么 |
|---|---|
| **接着跑** | 继续这条任务，保留已经做过的步骤和产物 |
| **换个说法重新派** | 把原来那句话填回输入框，改了再派（从头新开一条） |
| 重跑一次（/runs 上，工作流专用） | 从头新开一条记录 |

「接着跑」与「重跑一次」语义相反，两个按钮各带一句 hint 说清楚——不说的话用户建立不起预期。

## 五、界面上不摆「点了必定报错」的按钮

同事的运行也看得见（从运行中心点进来），那是刻意的。但确认、追问、接着跑、终止
**只有发起人做得了**（服务端会拒）。所以 `AgentTurn` 带上 `mine`，界面据此渲染：

- 不是我发起的 → 一个按钮都不摆，改为一句说明「这一步在等发起人确认（这次执行不是你派的，
  你看得到过程但推不动它）」；
- 徽章也跟着换人称：「等你确认」对推不动它的人是句错话，而**徽章比说明先入眼**。

这与 /runs 不放确认按钮是同一条理由。

## 六、顺手收的一处过时文案

批 1 给 AI 执行接上通知之后，执行面板那句「跑完会在通知里告诉你」还只对「等插件」那种说
（那是通知接上之前的正确写法）。现在所有挂起态都真的会通知，文案一并放开。
守卫 `tests/agent/transition.test.ts` 盯着这两件事的一致性：通知没接上时不许承诺，接上了就该说回来。

## 守卫

新增 `tests/agent/notes.test.ts`（21 条）。**十七条 mutation 逐条验过会红。**

其中一条是 mutation 抓出来的**假绿**：「附言跟着运行记录删」那条守卫原本只检查
`26-agent-note.sql` 里有没有建表，没检查外键的 `ON DELETE CASCADE`——
而**生产靠的是那份 SQL，不是 schema.prisma**。漏了级联的话，运行记录到期清理会撞 FK 报错，
或者留下一堆永远没人读的孤儿附言。已补上对 SQL 与两份 schema 的三向断言。

另外顺手修掉一个自己刚造的「写了没接」：`goalOf()` 从步骤流水里找 `kind === 'goal'`，
而那种 kind **根本不存在**（AgentStep 的 kind 只有 tool_call/tool_result/answer/rejected/error），
它永远返回空字符串。改成服务端直接把 `goal` 带出来——它本来就在运行行上。

## 回滚

代码可直接回滚。新表留着不用即可（旧代码不读它）。
若已在生产跑过一段：回滚后那些还没送达的附言不会再被消费——
建议回滚前先看一眼 `SELECT count(*) FROM "AgentRunNote" WHERE "consumedAt" IS NULL`，
不为零就等它们跑完再回滚。
