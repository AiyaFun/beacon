# 上线清单 · 2026-08-18 这一轮（七项新功能）

这一轮加了七件东西，**其中四件需要在生产库手动建表**。不跑这几条 SQL，对应页面会在
运行时报「表不存在」——而且是 500，不是降级。顺序无所谓，但都要跑。

## 一、生产库手动执行（必做）

在能连到生产库的机器上，或 `docker compose exec web`：

```bash
DATABASE_URL="postgresql://beacon_app:<PWD>@<HOST>:<PORT>/postgres?schema=beacon&sslmode=require" \
  npx prisma db execute --schema prisma/schema.postgres.prisma --file prisma/postgres/06-platform-ops.sql
```

四份文件，逐个执行（全部幂等，重复跑安全）：

| 文件 | 建了什么 | 不跑会怎样 |
|---|---|---|
| `06-platform-ops.sql` | `Member.platformAdmin` 列、`Tenant.status/suspendReason` 列、`LlmCallLog.source` 列、`AdminAuditLog` / `PlatformProvider` / `PlatformSetting` / `AgentRun` / `AgentStep` | 运维台 500；AI 执行模式 500；登录链路读 `Tenant.status` 报错 |
| `07-publish.sql` | `PublishPlan` / `PublishTask` / `PublishCredential` | 一键发布 500 |
| `08-workflow.sql` | `WorkflowTemplate` / `WorkflowInstall` / `WorkflowRun` | 工作流模板页 500 |
| `09-parser-learn.sql` | `ParserIncident` / `ParserRule` | 插件上报解析样本 500（插件侧是静默失败，看不出来） |

⚠️ `06` 里那三个 `ALTER TABLE ... ADD COLUMN` 是**先于**代码上线跑更安全：
新代码会读 `Tenant.status`，老库没有这一列时每次登录都会抛。

## 二、环境变量（新增一个，可选但强烈建议）

```
BEACON_PLATFORM_ADMINS=13800000001,ops@example.com
```

逗号分隔的手机号或邮箱，写在里面的人登录后即为**平台超级管理员**，并自动把
`Member.platformAdmin` 补写回库。不配的话库里一个超管都没有，`/ops` 谁都进不去
（这是先有鸡还是先有蛋的死结，env 是唯一的钥匙）。

之后可以在 `/ops/tenants` 里互相授予，但**env 白名单里的人收不回**（如实报错，
不假装收回了）——要撤销得先改 env 再重启。

## 三、插件（0.9.4）

`npm run pack:ext` 会随构建自动打包。这一版新增：

- `content/publish-fill.js`：在五个创作者后台把内容填进发布表单，**不点发布按钮**；
  ⚠️ **选择器尚未真机校准**，填不进去时会如实提示并把内容复制到剪贴板。
  真机校准是上线后第一件该做的事（抖音/小红书/B站/视频号各一次）。
- `content/common.js`：解析失效时上报**脱敏结构骨架**（只有形状没有内容）；
  规则包缓存与兜底选择器。
- `sw.js`：`publish:pending` / `publish:receipt` / `parser:miss` / `parser:refresh` 四条消息；
  每日闹钟顺带拉一次解析规则包。

三份隐私政策已同步更新（网页版 / `extension/store/privacy.md` / 商店托管的
`privacy-policy.html`，最后一份由 `npx tsx scripts/privacy-page.ts` 生成）。

## 四、上线后要做的验证（按顺序）

1. 用 env 白名单里的号登录 → 顶栏出现「运维台」→ 进 `/ops` 能看到租户列表。
2. `/ops/ai` 加一条平台渠道 → 「测试」通 → 随便触发一次 AI → `/ops/ai` 的「今日调用」+1，
   且「按付费方」那栏出现 `平台垫付`。
3. `/ops/ai` 加一条**火山方舟（豆包）**渠道 → 「按功能路由」里把「封面生图 · 仅火山方舟」指到它
   → 用一个**自己没配任何 Key** 的租户去生成封面：应当能出图，且 `/ops/ai` 的
   「按付费方」出现 `平台垫付`。（2026-08-19 补：此前生图只认租户自己的豆包渠道，
   平台配了也不生效——运维台有开关、读侧没人读。）
4. `/assistant` 切「执行」→ 说「帮我建一篇草稿」→ **必须先弹确认**才建。
5. `/workflows` 装一条内置模板 → 跑一遍 → 每步都有结果行。
6. `/studio` 选一篇有正文的稿子 → 「一键发布」→ 勾几个平台 → 生成计划 →
   公众号那条显示「官方接口直发」，抖音那条显示「插件半自动（你点发布）」。
7. 公众号直发要先在「设置 · 发布通道」填 AppID/AppSecret，并把**服务器出口 IP**
   加进公众号后台白名单（否则报 40164，文案里已经写清楚了）。

## 四之二、页面搬家（2026-08-19）

密钥类配置全部收进 **`/settings/keys`「接入与密钥」**一页：模型渠道（BYOK）与按功能路由、
生图、公众号发布凭证、插件采集令牌、机器人凭据，页首还有**一键检测**。
原 `/settings` 改名「运行设置」，只剩自动化任务 / 数据源 / 语义向量；
`/notifications` 只管「推送什么、什么时候推」，没配机器人时给出去填凭据的指引。

上线后要看的：
- 侧栏出现「接入与密钥」与「运行设置」两条（原来的「模型与设置」没了）；
- 各处报错文案里的「设置 · 模型接入」已统一改成「接入与密钥」——点进去要能直接看到输入框；
- 在「接入与密钥」点一次「一键检测」：模型渠道逐条出结果，且**群里不该收到任何测试消息**、
  账上**不该多一次出图**（检测刻意不做这两件事，纯 Webhook 机器人会如实标「测不了」）。

## 五、这一轮明确**没做**的事（别当成漏了）

- **YouTube / X / TikTok 的直发**：YouTube 要上传视频文件本身，而系统只存文案与封面；
  X 要付费 API 套餐；TikTok 要企业资质。三者都走「手动发布」并在界面上写明原因。
- **公众号自动群发**：默认只写进草稿箱。群发不可撤销、订阅号每天一次机会，
  必须用户显式勾「同时提交群发」。
- **插件代点发布**：不做，任何平台都不做。
- **AI 改代码**：执行器只能调用注册表里的工具（`lib/agent/tools.ts`），
  没有也不会有「让 AI 写段代码跑一下」的通道。
- **解析规则自动上线**：模型给的选择器只能是候选，必须在 `/ops/parser` 人工采纳。
- **用非方舟的 Key 生图**：生图的显式 AI 水印靠的是即梦的 `watermark` 参数（《标识办法》第四条
  要求的显著标识）。别家图像端点参数形状不同、也没有可强制开启的水印开关——拿它出图等于
  交付一张没有显式标识的封面。所以「封面生图」这一行只让选火山方舟渠道，指到别家会当场拒绝
  并说明原因，而不是静默降级。
