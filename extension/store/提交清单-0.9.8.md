## 1. 这一版为什么要重新提交（一句话给你自己记）

**把「公众号竞对采集」的风险确认闸装进插件。** 之前这道合规闸只有服务端侧的文案生效，
真正拦在用户端的那道闸在插件里——**不上架这个版本，等于那道合规闸没在用户端生效**。

具体变化（都在包里，已验证）：
- `sw.js`：`collectWechatOne` 最前面加风险确认闸，未确认返回 `risk_unacked`、一个请求都不发。
- `popup.html` / `popup.js`：首次点「后台采集」弹出必须勾选的风险确认面板。
- `options.html` / `options.js`：设置页新增「公众号竞对采集（默认关，风险自负）」开关。

## 3. ⚠️ 最容易栽的一步：隐私政策 URL 必须**境外可达**且**已更新**

Chrome 审核机器在**境外**，而 `beacon.iyunci.cn` 在国内节点、**境外访问不通**
（宝塔 WAF 把境外 IP 444 掉——这正是历史上「无法访问隐私权政策链接」被打回的真因）。
所以商店那一栏填的隐私政策 URL 必须是一个**托管到境外**的静态页。

这一版隐私政策已经改了（补了公众号采集风险、数据来源方披露、评论去标识化表述），
对应的境外托管版**已重新生成**：

```
extension/store/privacy-policy.html   （2026-08-24 已按线上重新生成，含 0.9.8 的全部更新）
```

**你要做的**：
1. 把这份 `privacy-policy.html` 传到你的境外静态托管（GitHub Pages / Cloudflare Pages / Vercel 等）。
2. 打开那个 URL，从**你自己的手机流量或境外网络**确认能打开（别用能连国内的网络测，会假绿）。
3. 商店「隐私政策 URL」栏填这个**境外 URL**——不要填 `beacon.iyunci.cn/legal/privacy`（审核机打不开）。

> 如果上一版上架时已经用了某个境外 URL，**用同一个 URL、只更新那份 html 的内容**即可，
> 不用换地址（换地址商店要重新验证）。

## 4. 提交步骤（devconsole）

1. 登录 <https://chrome.google.com/webstore/devconsole>（你本人的开发者账号）。
2. 打开**已上架的「烽火台采集助手」**这个项目（不是新增项目）。
3. 「软件包」→ 上传新 zip `beacon-collector-0.9.8.zip`。
4. 「隐私权做法」：确认隐私政策 URL 指向**已更新的境外托管页**（第 3 条）；
   权限用途、单一用途说明**照旧不用动**（这版没变）。
5. 提交审核。更新提交通常比首次快（1–3 个工作日）。

---

## 5. 审核通过后（一件事，别忘）

把在架版本号 env 更新到 0.9.8，下载页才敢并排显示「商店版 v0.9.8」：

```
BEACON_EXT_STORE_CHROME_VERSION="0.9.8"
```

改在生产的 `.env.production`，然后重启 web（`bash scripts/deploy-swap.sh` 或 `docker compose restart web`）。
口径见 `lib/downloads.ts`。
