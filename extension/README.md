# 烽火台采集助手（浏览器插件）

竞对监控的 **authorized 通道**（方案三 · 众包采集）：你自己浏览竞对**公开主页**时，
把页面上你亲眼可见的公开数据一键回传到烽火台竞对档案。抖音/小红书在未接商业数据源时，
这是唯一不碰灰色地带的指标来源。

## 合规设计（红线，改代码前先读）

- **只在你真实打开的公开主页上采集**：两种触发都要求你人在页面上——手动「采集本页」，或
  **访问即采**（打开已订阅竞对主页时自动采一次，可在设置关闭）。**不设轮询定时器、不后台开页抓取、
  不碰登录态接口**——采的永远是你亲眼可见的已渲染公开 DOM（作品列表/粉丝数）。
- **唯一的页面交互是「向下滚动」**（翻页采集，见「使用」第 5 条）：作品列表懒加载，不滚就只有首屏那 20 条。
  滚动是浏览器里的普通操作，**不点击任何按钮、不调用平台任何接口、不发任何请求**，读到的仍是
  「你自己滚下去也能亲眼看到」的同一批公开数字。且只在你主动点采集、或在后台标签页里发生，
  采完还原滚动位置，有硬上限（≤12 次 / ≤30 秒 / ≤50 条）。改这块要同步 `store/privacy.md`。
- **访问即采的两道闸**：① 设置里可关；② 只对**已订阅竞对**自动采（内容脚本先向后台核对订阅清单缓存，
  非订阅账号静默跳过、不发任何请求）。它只是把"你本来要点的那一下"自动化，不改变"只在你看时采"的性质。
- **每日提醒 = 提醒你去看，不替你抓**：`chrome.alarms` 每天在图标上显示"今日待刷新数"角标 + 可选系统通知；
  点开弹窗里的竞对，由**你**决定是否打开其主页。提醒本身不发起任何采集。
- **只进已订阅的竞对**：服务端三道守卫（令牌 → 工作区订阅关系 → zod 形状校验），
  未订阅的账号回传会被 403/404 拒绝。见 `lib/ingest/competitor.ts`。
- **host 权限只有 8 条路径（0.8.2 起）**：B站/抖音/小红书/YouTube/X/TikTok 的公开作品页，
  与早已声明的内容脚本注入范围**完全相同**，不含任何创作者后台域名。回传/拉清单**仍然不靠它**
  （服务端 CORS + 令牌头）。加它的唯一原因：`activeTab` 只在用户点**扩展自己的 UI**
  （图标弹窗、右键菜单）时授予，点**页内侧栏**上的按钮拿不到——「读评论提问」要在侧栏可用就绕不开。
  `alarms`/`notifications` 用于每日提醒。改这条要同步 `store/privacy.md` 的权限表。
- **评论提问采集（0.8.2）**：默认关，两个独立开关（自有 / 竞对）。只读**当前屏幕上已显示**的评论，
  不滚动、不翻页、不展开；只取提问短句，**不取昵称/头像/主页/用户ID/IP属地/时间/点赞/回复关系**。
  归属（自有还是竞对）由**页面那一侧**判：`content/comments.js` 把 `selfOnly` 与作者 `handle`
  随结果带上来，SW 拿 handle 与已绑定账号比对——SW 里读 `globalThis.__beaconSelfOnly` 永远是
  undefined（那是内容脚本隔离世界的变量），曾因此把自己作品的提问全记成竞对，
  用例钉在 `tests/ingest/comment-scope.test.ts`。
  ⚠️ **选择器全部未经真机校准**：上线前在作品页控制台粘贴 `tools/comments-probe.js`，
  它会逐条报现行选择器命中情况、两道闸判定，并在落空时扫出候选容器/条目选择器。
  探针内嵌的规则副本与 `content/comments.js` 由测试钉死，不许漂移。

## 分发与安装

**用户入口**：app 内 `/extension`「下载采集助手」页——按浏览器给卡片（Chrome / Edge / 360 / Brave 同为
Chromium，同一个包通用；Safari 因需 Apple 签名 + App Store，标注「即将支持」）。商店链接优先，未上架时
回落到自托管 zip + 开发者模式加载。设置页/数据看板/竞对页三处也都有「去下载」入口。

**分发形态**（见 `lib/downloads.ts` / `scripts/pack-extension.ts` / `extension/store/`）：
- **商店（主）**：`npm run pack:ext` 产出 `public/downloads/beacon-collector-<ver>.zip`，
  **只传 Chrome 应用商店**（提交材料备在 `extension/store/`）。Edge / 360 / Brave 不单独上架，
  走 zip 开发者模式加载（理由见 `extension/store/PUBLISH.md` 第 2 节）。
  Chrome 上架通过后把详情页链接填进 env `BEACON_EXT_STORE_CHROME`，下载页即变「一键安装」。
- **自托管 zip（兜底）**：同一个 zip + 下方开发者模式步骤，用于内测/审核期/企业内网。
- **crx**：裸 crx 双击安装在新版 Chrome/Edge 已被封，不作分发主路径；企业内网强推用
  `chrome --pack-extension` 单独签名（见 `extension/store/PUBLISH.md`）。

### 开发者模式加载（zip / 本目录通用步骤）

1. Chrome 打开 `chrome://extensions` → 右上角开「开发者模式」（Edge 用 `edge://extensions`）
2. 「加载已解压的扩展程序」→ 选解压后的目录（或直接选本目录 `beacon/extension/`）
3. 插件设置页填两项：
   - **烽火台地址**：你的部署地址（如 `https://your-beacon.example.com`）
   - **采集令牌**：烽火台「设置 → 数据源 → 插件采集令牌」生成后复制过来
4. 点「测试连接」确认握手成功

## 使用

1. 先在烽火台「竞对监控」页添加/订阅竞对（handle 要与主页 URL 中的 ID 一致：
   B站=mid、抖音=sec_user_id、小红书=user_id）
2. **访问即采**（推荐）：直接打开竞对公开主页（B站空间页 / 抖音用户页 / 小红书用户页），
   等作品列表渲染出来，插件自动采集并在右下角提示"✓ 已自动采集…"。
3. **竞对清单中枢**：点插件图标 → 弹窗列出你订阅的竞对 + 今日刷新状态（绿点=已刷新/橙点=待刷新），
   点某条的「打开采集」直接跳到其主页（打开即自动采）。也可在任意支持页面点「采集本页」手动采。
4. **每日提醒**：每天在图标上以角标显示"今日待刷新数"，可选系统通知；点开弹窗按提示逐个刷新即可。
0. **一键更新（0.7.1 起）**：插件每 12 小时问一次 `/api/ingest/version`，有新版就在弹窗顶部出一条提示。
   点「一键更新」的结果**取决于你怎么装的**，这不是偷懒，是 Chrome 的硬限制：
   - **商店安装** → 走 `requestUpdateCheck()` 拉更新，成功后自动重载插件，真·一键；
     若商店那版还在审核（商店版天然滞后于自托管 zip），会如实说明并建议下 zip。
   - **开发者模式加载的 zip** → 浏览器**不允许任何扩展给自己换文件**。能做到的极限是替你把新 zip
     下下来并打开扩展管理页，剩下「解压覆盖 + 点重新加载」必须人来。文案里写明白了，不做假按钮。
   设置页「版本与更新」里也能手动查，会告诉你当前版本、安装方式、有没有新版。

5. **翻页采集（0.7.0 起）**：各平台主页的作品栅格都是懒加载的，首屏只渲染 18–20 张卡片——
   此前「采集本页」采到的一直是首屏那点东西，一个 478 条作品的号也只采到 20 条。
   现在点采集后会**在页面内向下滚动**，等平台把后续作品渲染出来再读，直到够 50 条 /
   连着两轮不再增长 / 超出 30 秒预算。三条约束：① 只有**用户主动点采集**、或页面本来就在
   后台标签页里（批量采集打开的那种，`document.hidden`）才滚，用户正看着的页面不动它；
   ② 采完把滚动位置还回去；③ 创作者后台不翻页（那儿是分页按钮，不是滚动加载）。
   **50 是硬上限**：服务端 `posts.max(50)`，超一条不是多的被截掉，而是整批被 zod 打回。
   各站点解析器统一读 `common.js` 的 `BEACON_POST_CAP`，别各写各的数字。
   同一个号多采几次会累积——入库按 `(platform, platformItemId)` upsert，不会重复。
6. **详情页深度指标**：主页列表页通常只看得到播放/点赞；**评论、收藏、分享、投币、弹幕**这些
   只在单条内容的**详情页**才显示。在 app「竞对监控」里点作品标题（↗）跳到原内容详情页，插件会
   自动把这条的完整指标采下来，合并进该作品档案（缺项不覆盖已有值）。支持：
   B站视频页 `bilibili.com/video/*`、抖音视频页 `douyin.com/video/*`、小红书笔记页 `xiaohongshu.com/explore/*`。
   **X（Twitter）**：`x.com/<用户名>` 主页 + `x.com/<用户名>/status/<id>` 推文页。x.com 国内被墙，需你自己
   挂 VPN 且登录 X 后浏览竞对主页采集（指标从推文操作栏读取：回复→评论、转推→分享、点赞、浏览）。
   **YouTube**：`youtube.com/@handle/videos` 频道页 + `youtube.com/watch?v=<id>` 视频页。国内被墙需挂 VPN，
   但频道页公开、不用登录。频道页采视频列表+播放量，视频页采点赞（建议按 @handle 添加竞对，handle 才对得上）。
   **TikTok**（0.7.0 起）：`tiktok.com/@<用户名>` 主页 + `tiktok.com/@<用户名>/video/<id>` 作品页。
   国内被墙需挂 VPN，但主页公开、不用登录。主页采九宫格作品列表 + 播放量 + 粉丝数，作品页采
   点赞/评论/分享/收藏。**handle 存不带 @ 的用户名**（与 X 同口径，`mrbeast` 而不是 `@mrbeast`）。
   身份只认 `/@` 开头的路径——`/foryou`、`/explore`、`/tag/xxx` 这些功能页一律不建账号。
   和 X 一样没有创作者后台可认：你自己的数据就在你自己主页上，所以主页上点「这是我的作品」
   要多一次确认（读到「编辑资料 / Edit profile」才直接放行）。
   **公众号竞对**（`content/wechat-competitor.js`，0.6.0 起）：公众号没有公开网页主页，所以不走
   「打开竞对主页顺手采」，而是在**你自己已登录的公众号后台**（`mp.weixin.qq.com/cgi-bin/*`）里，
   用当前地址栏的 token 同源调后台自带的两个接口——`searchbiz`（按名字搜号）+ `appmsgpublish`
   （拉该号的公开图文列表）。竞对名字必须与后台搜索显示的**完全一致**（搜不到会把候选名报回来，
   不猜）。只取标题/链接/发布时间，**不取阅读量/在看**（那要抓包截取微信客户端凭证，不做）。
   **采集节奏写死且在网页上明示**（`lib/wechat-collect-rules.ts` 是唯一事实源，插件里的数字与它
   由测试钉死）：每次只取最近 7 天、最多翻 2 页，请求间隔随机 3–6 秒，同号 12 小时一次
   （**只按你自己的采集记录算**，别人采过不拦你——冷却是保护你自己那个后台账号的频率预算），
   一轮最多 5 个号、换号间隔 30 秒，撞频控立即停手并冷却 30 分钟。用的是用户自己的号，慢比快重要。
7. **一键采集全部**：app「对标账号」卡片右上角、或插件弹窗里点「⚡ 一键采集」，插件会**依次**在后台
   标签打开每个可采集竞对的主页 → 访问即采采完 → 关闭 → 下一个，并显示进度。app 页无法自己驱动
   多标签采集（浏览器拦截多开），故这颗按钮由插件驱动：app 端按钮通过 `content/bridge.js`（只注入
   烽火台域名）把点击转发给后台编排。用户一次点击触发、后台标签、采完即关，不做无人值守定时。

8. **创作者后台 · 自有数据回填**（`content/self-backend.js`）：只做**自有数据**，不采竞对。
   在你自己的创作者后台「数据中心 · 作品数据」页点「📥 这是我的作品 · 回填数据看板」，
   插件读取该页已渲染的**你自己作品**数据，走 `/api/ingest/self` 回填。支持：
   视频号 `channels.weixin.qq.com/platform/*`、公众号 `mp.weixin.qq.com/cgi-bin/*`（只认后台，
   不认 `/s/*` 文章正文页）、抖音 `creator.douyin.com/*`、小红书 `creator.xiaohongshu.com/*`、
   B站 `member.bilibili.com/*`。
   **为什么值得走这条**：公开作品页拿不到**完播率/完读率**，而它是抖音/公众号/B站/视频号算法的
   第一信号，也是「平台算法教练」的个性化诊断此前总说样本不足的原因。创作者后台是唯一能合规拿到它的地方。
   边界：**仅本人登录态、只读（不发布不修改不删除不调接口）、仅自有数据、不采集他人**，
   不读取也不上传任何平台的 Cookie/登录凭证，也不代你登录；**不参与「访问即采」**，必须手动点击触发
   （`self-backend.js` 置 `__beaconSelfOnly`，`content/common.js` 的自动采集据此跳过）。
   ⚠️ 各后台 DOM 未在真实登录态下实测校准，选择器用多重回退；失效时只改 `self-backend.js`，不动后端。

9. **X · 自有数据回填**（`content/x.js`）：X 上**没有**创作者后台这种独立域名可认——浏览量在 X 上
   对所有人公开，你自己那条推的数字，和竞对那条推的数字，在同一个 DOM 位置。所以 X 的自有通道认的是
   「你自己的主页 / 你自己的推文页」：`x.com/<用户名>`、`x.com/<用户名>/status/<id>`（保留路径
   `/home` `/explore` `/i/*` 等除外）。在这些页面上，插件弹窗与 SidePanel 会同时给出两个按钮——
   「加为竞对并采集」和「这是我的作品 · 回填数据看板」。
   ⚠️ **页面本身分不出是谁的号**，点错不是「采得不准」：竞对的 20 条推文会被写成你自己的发布记录，
   污染数据看板与基线、喂进学习样本，且没有一键撤销。所以 `x.js` 会找「编辑资料」/「查看帖子数据
   （`/status/<id>/analytics`）」这类**只有本人可见**的入口，找到才带 `isSelf:true` 直接放行；
   找不到（含 X 改版让选择器失效）要求在同一地址上**再点一次**确认。
   能拿到的指标：浏览、点赞、回复→评论、转推→分享 + 发表时间（`<time datetime>`）。
   X 没有完播/完读率这类只有后台才有的指标，所以这条通道不解决「算法教练样本不足」，只解决
   「我自己的 X 数据进不了数据看板」。回填前工作区里要先有一个 **X 平台的账号**（数据看板按账号分开看）。
   前置：x.com 国内被墙，需你自己挂 VPN 并登录 X。

10. **收进灵感箱**（第三条通道 `/api/ingest/inspiration`）：不认平台、不写竞对库、不写发布记录，
   只往你自己工作区的收集箱加一行（标题 + 链接 + 备注，**不存正文**——存正文是搬运）。
   入口有四个，**都不随页面类型显隐**：插件弹窗、SidePanel、页内侧栏，以及右键菜单
   （选中文字 → 「收进烽火台灵感箱」，选中的话进备注栏；整页 → 「把这个页面存为灵感」）。
   为什么强调常驻：日常点悬浮胶囊打开的是 SidePanel（Chrome 116+ 上页内抽屉根本不展开），
   而这颗按钮此前只长在抽屉里；在 X 这类既没有创作者后台、又可能压根不是自己号的地方，
   「记一笔」常常是唯一能做的事。
   URL 里 `token/sid/ticket` 一类等同于登录态的参数在 `sw.js` 的唯一出口统一抹成 `***` 再上传。

11. **回填到哪个账号**（`GET /api/ingest/self/accounts` + `chrome.storage.sync.selfAccountId`）：
    归属此前是**猜**的——服务端按平台取同平台第一个活跃账号（`lib/ingest/own-post.ts pickAccountFor`）。
    一个工作区经营两个抖音号时这必然错一半，而挂错账号在数据看板上是**彻底看不见**
    （每个数据页都是 `where accountId = 当前选中账号`），还会带着另一个号的数字污染基线与学习信号。
    现在插件里可以绑一个账号：设置页 + 弹窗 + SidePanel + 页内侧栏四处都有「回填到」下拉框，
    存 `chrome.storage.sync`（四处共用），由 `sw.js` 的 `ingestSelf` **统一**挂到请求上——
    挂在各个入口的点击处理里迟早会漏一个，而漏掉的那个入口发出去的数据又会被后端按平台猜。
    不选 = 保持旧行为（后端按平台匹配）。绑定的账号不在工作区、或平台与当前页对不上时，
    服务端**报错而不是回退去猜**（`resolveTargetAccount`）——任何一种自动选择都可能是错的，
    而错了要到数据看板上才发现。

12. **AI 助手读当前页正文**：助手此前拿到的上下文只有标题 + 几个数字，于是「爆款要点拆解」
    拆的其实是一个标题。现在 `content/common.js` 的 `beaconPageText()` 取可见正文
    （信息流站点按 `article` 逐条取，其余取 `main`），随 `context.snippet` 一起发给
    `/api/ingest/assistant`（该字段服务端一直支持，只是从来没人往里塞过东西）。
    三条约束：**只在用户点「拆解/衍生/发送」时才取**、4000 字符硬上限、跳过我们自己注入的侧栏
    （否则助手会把自己上一轮的回答当成页面内容）。

## 设置项

- **烽火台地址**：默认 `https://beacon.iyunci.cn`，一般不用改。
- **采集令牌**：烽火台「设置 → 数据源 → 插件采集令牌」生成；设置页有「↗ 打开烽火台设置页」快捷跳转。
- **访问即采**开关（默认开）、**每日提醒**开关（默认开）。

## 服务端接口

- `POST /api/ingest/competitor` — 回传采集数据（令牌头鉴权，三道守卫）。
- `GET  /api/ingest/competitor/list` — 拉取本工作区订阅竞对清单（供弹窗列表 + 每日提醒）。
- `POST /api/ingest/self` — 回传自有作品/账号数据（可带 `accountId` 指定归属账号）。
- `GET  /api/ingest/self/accounts` — 拉取本工作区创作账号清单（供「回填到」下拉框）。只回
  id/名称/平台/handle/状态；人设卡、风格指纹这些工作区核心资产不从这条免 cookie 的通道出去。
- `POST /api/ingest/self/accounts` — 就地建号。**由 `sw.js` 的 `ingestSelf` 自动调用**：
  回填收到 `no_account*` 时，用页面上的昵称（`profile.name`；创作者后台的 handle 恒为 `'self'`，
  那儿退到「公众号账号」这类平台名兜底）建号 → 绑定 → **立刻重试回填**，一次点击走完。
  只重试一次（建完仍报没账号就如实失败，否则是无限建号）；别的失败（令牌无效/超时）不触发建号。⚠️ 采集令牌**唯一**能创建工作区实体的地方：
  网页里建号要 `persona.edit`（viewer 不能建），而设置页令牌卡没有角色门，故拿到令牌的 viewer
  可经此建号——这是产品上明确接受的取舍（2026-07-27，取最少操作）。口子只开到「建一个空账号」：
  不能改名、不能删、同名同平台幂等、总数封顶 30、人设种子与网页建号一致、每次建号记日志。
- `POST /api/ingest/inspiration` — 收进灵感箱。
- 均在 `middleware.ts` 的 PUBLIC_PATHS 白名单内（`/api/ingest/competitor` 前缀覆盖），CORS 全开、令牌鉴权。

## 维护提示

内容脚本的 DOM 选择器（`content/*.js`）随平台改版可能失效——全部写成多重回退，
失效的表现是"采到的字段变少"而不是报错。改选择器只动 `content/` 下对应站点文件即可。
图标由 `node /tmp/genicon.js`（一次性脚本，已删）生成的纯色 PNG，可自行替换 `icon16/48/128.png`。
