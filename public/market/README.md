# 技能市场目录

`index.json` 是市场的**唯一目录**，客户端（含整机版）从这里拿「有哪些现成的可以装」。

## 为什么是一个静态 JSON

市场第一版只要回答一个问题：有哪些现成的东西可以装。一个静态目录 + 一个包地址就够了，
而且它有两个别的做法给不了的好处：

- **整机版也能用**。客户那台 Mac mini 连的是自己的服务端，但目录可以指向官网——
  否则整机版装完就是一个永远长不出新东西的离线快照。
- **发布不用发版**。加一个技能就是往目录里加一条。

## 加一条

```json
{
  "kind": "skill",
  "slug": "xhs-punch",
  "name": "小红书爆改",
  "description": "把平铺直叙的文案改成小红书调性",
  "emoji": "📕",
  "version": "1.0.0",
  "author": "烽火台官方",
  "platform": "xiaohongshu",
  "url": "https://beacon.iyunci.cn/market/packs/xhs-punch.json"
}
```

`url` 指向的那个文件必须是 **beaconPack 格式**（见 `lib/market/pack.ts`）：

```json
{
  "beaconPack": 1,
  "pack": {
    "kind": "skill",
    "slug": "xhs-punch",
    "name": "小红书爆改",
    "version": "1.0.0",
    "platform": "xiaohongshu",
    "outputKind": "text",
    "promptTemplate": "请把下面的正文改写成小红书风格：\n{{content}}"
  }
}
```

## 三条硬规矩

1. **包里只有数据，没有代码**。技能是提示词模板、智能体是步骤 JSON、人设是一段文本。
   能力（agent 工具）与浏览器动作是代码白名单，**永远不进包**——那等于「下载代码执行」。
2. **slug 一旦发布就不许改**。它是「同一个东西的新版本」的认人依据，改了就等于换了个东西。
3. **版本只增不减**。旧版本盖不掉新版本（安装那侧会拒绝），但发一个版本号更小的包
   仍然会让用户困惑——发布前对一下当前线上的版本。

## 目录里的 author 不是认证

包里的 `author` 只是一行字，**没有签名机制**。界面上已经明写「来源仅供参考」。
一阶段官方目录靠人工审核把关：能进这个文件的东西都是看过的。
